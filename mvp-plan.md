# mvp-plan.md — тест «первые 10 минут» (итерация 1)

План по циклу из [process.md](process.md). Статус чек-листов обновляется по ходу.

## Гипотеза

Женщина 35+ из холодного трафика VK, открыв страницу без объяснений, понимает
правило с первого уровня и играет ≥ 3 минут; поток из 14 уровней с плавным
вводом механик удерживает её до конца.

## Носитель

Отдельная страница **https://artmartiros.github.io/hvostoed/mvp.html**:

- поток из 14 существующих уровней (доски не менялись, все прошли ворота CI),
  подобранных по метрикам брифа: 4 безопасных обучающих → первая авария →
  порядок → переезд → вылет → валуны → колючая → зрелищный финал «Кольцо» +
  бонус «Пир»;
- уровни только нумеруются, названий и выбора нет; следующий — в один тап;
- никакой дебаг-обвязки: без мастерской, флажков «Прислать», меню и штампа сборки;
- после последнего уровня — экран «Скоро будут следующие уровни»;
- аналитика встроена (см. ниже), основная игра по адресу `/hvostoed/` не тронута.

## Решающее правило (зафиксировано ДО запуска)

| метрика | как считается | зелёная | красная |
|---|---|---|---|
| открыл → сыграл | визиты с целью `first_move` / все визиты | ≥ 60% | < 50% → чинить вход или убить |
| доля сессий ≥ 3 минут | стандартный отчёт Метрики по времени визита | ≥ 25% | < 15% → убить |
| медиана уровней за сессию | по `level_finish(win)` в «Параметрах событий» (или Logs API) | ≥ 8 | < 5 → итерировать (искать стену по воронке) |

`level_start` шлётся автоматически при открытии уровня, поэтому «сыграл» меряет
ТОЛЬКО `first_move` — событие первого реального тапа-хода (одно на уровень).

«В производство» = все три зелёные и в воронке нет уровня, теряющего ≥ ⅓ игроков.
Вердикт — после ~500 сеансов из рекламы.

## Аналитика: что уже в коде и что вписать руками

В `mvp.html` вшиты Яндекс Метрика и пиксель VK Рекламы (top.mail.ru), оба
включаются ТОЛЬКО когда вписаны ID — в самом верху `mvp.html` в блоке
`HV_ANALYTICS`:

- `YM_ID` — счётчик Метрики: https://metrika.yandex.ru → «Добавить счётчик»
  (вебвизор и карту кликов включить), номер счётчика — в `YM_ID`;
- `TMR_ID` — пиксель VK Рекламы: https://ads.vk.com → «Сайты» → «Добавить
  пиксель», значение вида `3XXXXXX` — в `TMR_ID`.

События (шлются в Метрику как цели с параметрами; ключевые дублируются в пиксель):

| событие | параметры | зачем |
|---|---|---|
| `level_start` | `level` | открытие уровня (автоматическое) |
| `first_move` | `level` | первый реальный ход на уровне — «сыграл» |
| `level_finish` | `level, result: win/fail, attempt, duration_sec, moves, hints` | ядро воронки; `attempt` растёт при повторных финишах уровня («Ещё раз», отмена после «Не вышло») — для воронки берётся первый |
| `crash` | `level, cause` | «понял ли правило»: аварии на уровень |
| `hint_click` | `level` | зависимость от лампочки |
| `demo_complete` | `duration_sec` | дошёл до финального экрана |

Вехи «уровень N пройден» дублируются ОТДЕЛЬНЫМИ целями, потому что воронка в
Метрике по параметрам не строится (JS-цель — только идентификатор): в Метрику
уходят `level_1_win`, `level_3_win`, `level_8_win`, `level_14_win`; в пиксель
VK — `level_1_done`, `level_3_done`, `level_8_done`, `demo_complete` (на них
можно оптимизировать кампанию, когда наберётся статистика).

В Метрике после первого живого прогона: создать JS-цели
(Настройки → Цели → JavaScript-событие) с именами `first_move`, `level_1_win`,
`level_3_win`, `level_8_win`, `level_14_win`, `demo_complete`; собрать составную
цель-воронку `first_move → level_3_win → level_8_win → demo_complete`.
Пер-уровневый обрыв (где стена) — отчёт «Параметры событий» по `level_finish`
или Logs API.

## План по дням

**День 1 — код и деплой (готово этой веткой).** Страница, поток, аналитика,
проверки, сборка. После мержа в main CI выложит mvp.html на Pages.

**День 1–2 — руками владельца (≈ 1.5 часа + модерация):**
- [ ] счётчик Метрики → `YM_ID` в mvp.html;
- [ ] пиксель VK → `TMR_ID` в mvp.html;
- [ ] кабинет ads.vk.com: данные рекламодателя (ИНН/самозанятость) — без них
      кампания не выйдет из модерации; маркировку ОРД ВК делает сам;
- [ ] креативы: запись экрана 15–30 с (обед + переезд как «вау») + 2–3 статики,
      пометка «0+» на креативе и в тексте — иначе модерация завернёт;
- [ ] кампания: цель «переходы» (клики, НЕ конверсии — алгоритму нечему учиться
      на старте), таргет женщины 35–55 РФ, авто-UTM включить, ссылка на
      mvp.html; бюджет теста при CPC 30–80 ₽ и цели ~500 игроков — 15–40 тыс. ₽,
      стартовать с 2–3 тыс. ₽/день;
- [ ] отправить на модерацию УТРОМ — она занимает часы, бывает сутки.

**День 2–3 — запуск и присмотр.** Первые часы: сверить клики кабинета с визитами
Метрики (расхождение 10–20% — норма), посмотреть 10–20 записей вебвизора —
куда тычут на первых двух уровнях. Кампанию по первым часам не дёргать.

**День 3–5 — добор до ~500 сеансов и вердикт** по решающему правилу. Числа —
в бриф, вердикт — убить / итерировать / в производство.

## Известные ограничения теста (приняты осознанно)

- Клик из VK открывается во встроенном вебвью: возврат назавтра почти невозможен,
  поэтому D1 не меряем и не обещаем — только день 0.
- Куки-баннера нет: объём маленький, риск принят; счётчики стартуют сразу.
- Звука в игре нет (вибрация — только Android). Кандидат №1 на итерацию 2.
- Adblock режет счётчики у единиц процентов; в вебвью VK блокировщиков
  обычно нет.
